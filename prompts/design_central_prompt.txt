1. TRAZABILIDAD REQUISITO → ELEMENTO DE DISEÑO

Para cada requerimiento incluido en "requerimientos_contextualizados",
establece su relación con uno o varios elementos de "elementos_diseno"
únicamente cuando exista evidencia suficiente en:

- descripcion_general
- responsabilidad de los elementos
- relaciones
- restricciones
- decisiones_diseno
- observaciones

No fuerces una relación.

Si no existe evidencia suficiente para asociar un requerimiento con ningún
elemento, colócalo en "requisitos_sin_relacion_evidente" en lugar de
"trazabilidad_diseno".

Una relación puede ser de muchos a muchos: un requerimiento puede
relacionarse con varios elementos, y un elemento puede relacionarse con
varios requerimientos.

La "justificacion" debe explicar qué evidencia concreta del Diseño permite
establecer la relación (o la ausencia de ella).

REGLA IMPORTANTE:
No relaciones un requisito con un elemento solamente porque ambos aparecen
en el mismo Issue.

2. NIVEL DE CONFIANZA

La "confianza" únicamente puede ser:
- alta
- media
- baja

alta: la evidencia relaciona explícita y directamente el requerimiento con
el elemento (por ejemplo, la responsabilidad del elemento describe
literalmente la acción del requerimiento, o existe una relación entre
elementos que sustenta el vínculo).

media: existe evidencia parcial o indirecta que sugiere la relación, pero
no la confirma de forma explícita.

baja: existe una posible conexión temática, pero la evidencia es débil o
ambigua.

No uses una relación de confianza media o baja como si estuviera
confirmada. Consérvala como evidencia, no como relación consolidada.

3. REGLA ANTI-INVENCIÓN

No agregues, salvo que aparezcan literalmente en la evidencia recibida:
- bases de datos
- APIs
- microservicios
- frameworks
- protocolos
- mecanismos de autenticación
- servicios externos
- almacenamiento
- cifrado
- componentes adicionales

No inventes elementos de diseño para "completar" la trazabilidad.

4. CLASIFICACIÓN EXHAUSTIVA Y EXCLUYENTE

Cada requerimiento válido recibido en "requerimientos_contextualizados"
debe aparecer exactamente una vez, ya sea en "trazabilidad_diseno" o en
"requisitos_sin_relacion_evidente", nunca en ambos ni en ninguno.

5. CONSERVACIÓN LITERAL

Los campos "elementos_diseno", "restricciones", "decisiones_diseno" y
"observaciones" del resultado deben conservar exactamente el contenido
recibido en la evidencia de entrada, sin agregar ni eliminar elementos.

El campo "relaciones_normalizadas" debe conservar exactamente las
relaciones recibidas en el campo "relaciones" de la evidencia de entrada.

No uses ningún campo que implique una evaluación de Calidad o Seguridad,
como estados, porcentajes o niveles de aseguramiento.
